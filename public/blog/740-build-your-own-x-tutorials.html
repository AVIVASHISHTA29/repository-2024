740 Free Tutorials to Build Git, Redis and Docker From Scratch Before 2027

Published September 2026 · avivashishta.com

You commented build, so here are all 740 tutorials, free, with a link for each. Every one of them walks you through building a real piece of technology from scratch: your own Git, Redis, database, shell, Docker, operating system, programming language or neural network. I checked every GitHub-hosted link on 28 September 2026 and dropped the dead ones. The rest come from lists their maintainers keep updated, so if one has moved, tell me and I'll fix it.

What I cannot create, I do not understand. (Richard Feynman)

The short version: Part 1 has 357 "build your own X" tutorials, grouped by what you're building. Part 2 has 383 project tutorials grouped by language and framework. Pick one from the list of 8 below, finish it in a weekend, and put it on GitHub.

The two repos

The 8 I'd start with

  1. Write yourself a Git! (Python). You'll never be scared of Git again.
  2. Write a Shell in C. Short, and it teaches you how processes actually work.
  3. Let's Build a Simple Database (C). Every DBMS interview question starts making sense.
  4. Build Your Own Redis from Scratch (C++), or the Go version.
  5. Linux containers in 500 lines of code. This is what Docker is underneath.
  6. Implement a Neural Network from Scratch (Python). The best on-ramp to AI engineering.
  7. Crafting Interpreters. The classic free book on building a programming language.
  8. Build Your Own Text Editor (C). About 1,000 lines, and you'll understand terminals for life.

How I'd use this

  • Don't read tutorials, type them. Then change one thing the tutorial didn't do.
  • Pick the language you want a job in, not the one the tutorial author picked. Most topics have several languages.
  • Push every one to GitHub with a README that explains what you learned. "Built my own Git from scratch" starts better interview conversations than any LeetCode count.
  • After two or three of these, try the same idea on something AI: your own vector database, your own agent loop, your own tokenizer.
