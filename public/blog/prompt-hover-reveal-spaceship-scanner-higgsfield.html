The Prompt I Used to Build a Hover-Reveal Spaceship Scanner, with Higgsfield-Generated Hull Layers

Published August 2026 · avivashishta.com

Overview

A 1.4-kilometre starship on pure black, and it looks dead. Cold grey plating, dark engine bells, no lights anywhere. Then you move the cursor over the hull and a soft circle of it wakes up — plasma light running along every panel seam, orange-hot machinery visible through open access sections, engine bells blazing cyan and magenta. Move away and it goes cold again.

The trick is that there is no 3D model and no shader doing lighting. There are two flat images of the same ship — one dormant, one fully powered — stacked exactly on top of each other, and the cursor punches a hole in the top one. That is the entire effect. It only works if the two images line up to the pixel, which is the part everybody gets wrong.

Below is the whole prompt, plus why each clause is in it. Images generated with Higgsfield (gpt_image_2), keyed and composited locally with numpy.

What it produces: a full-viewport hull that bleeds past the frame, a cursor torch that reveals the energised layer beneath, five subsystem nodes that light only their own region and open a HUD readout, and a parallax field of transparent asteroid and debris cutouts drifting at different depths. Idle for a couple of seconds and the torch drifts across the hull on its own so the effect stays discoverable.

Stack: one HTML file, one CSS file, one JS file — no framework, no build step. Plus 11 generated images and a numpy/PIL pass to key them. Page payload lands around 4MB.

The one idea that makes it work

Generate the dormant ship first. Then feed that image back in as a reference and ask only for the power state to change, with the camera, framing, scale and silhouette explicitly locked. You are not generating two ships. You are generating one ship twice, and the second pass is forbidden from moving it.

Ask for two ships independently and you get two different ships — the camera drifts, the hull redesigns itself, and a circular reveal shows a completely different vessel inside the circle. Nothing in CSS fixes that.

Deriving alpha per layer gives two slightly different silhouettes and the reveal edge will show it. Close gaps and fill enclosed holes so stars can't shine through dark hull panels. Why each part is in there

“Pixel for pixel identical composition”

The second pass is an edit, not a generation, and it needs to be told that six different ways: same camera angle, same framing, same position, same scale, same silhouette, same hull geometry. Redundant phrasing genuinely helps here. The measured result was bounding boxes agreeing within 6px across 3840px of image.

Verify alignment with an overlay, not a number

The obvious check is intersection-over-union on the two silhouettes. It lies. The dormant hull is dark, so thresholding drops most of it and IoU came back at 0.66 on a pair that was actually registered perfectly — the number was measuring brightness, not position.

Compare bounding boxes instead, and render a red/cyan channel overlay (dormant in red, energised in cyan) and look at it. If masts and panel edges ghost or double, the layers moved. If they sit on top of each other and the only difference is glow, you are fine.

One alpha mask, built from both layers at once

Both images come back on pure black backgrounds, so alpha can be derived from luminance instead of shipping a black rectangle. The catch: derive it per-layer and you get two subtly different silhouettes, and the reveal edge will show you exactly where they disagree.

So build one mask from the per-pixel maximum of both layers' luminance and apply that same mask to both. Fill enclosed holes too, or starfield will shine through dark hull panels like the ship is made of mesh.

Chroma green beats asking for transparency

For the debris, generating on a flat #00B140 screen and keying it yourself in numpy is better than any background-removal model. Greenness is G - max(R, B), which is strongly positive on the screen and negative on almost every real material, so a smoothstep over it gives clean soft edges. Despill by pulling G back toward max(R,B). Measured residual green on edge pixels came out around 2–5/255 — invisible.

One trap: if you fill holes to rescue translucent interiors, skip any enclosed pixel that is still strongly green. Otherwise you fill the genuine see-through gaps — the ring interiors of the gyroscope artifact, the gaps between the reactor cage struts — with solid green paint. Composite every cutout onto a magenta checkerboard and look before you trust it.

Soft elliptical masks, not clip-path

For the per-subsystem reveals, clip-path: ellipse() works but cuts a hard arc straight across the hull, which reads as a rendering bug. A radial-gradient mask with a feathered edge lets the energised patch fade into the cold plating instead. Same registration, much better result.

Cap the hull against viewport height, not just width

min(120vw, 1820px, 168vh) — the vh term is what keeps a 120vw-wide ship from running off the top and bottom on a short laptop screen. On portrait screens that same term inverts the problem and shrinks the hull to a third of the frame, so portrait gets its own rule: centre it and let it bleed off both sides.

What broke

  • Every subsystem marker was invisible. The coordinate custom property was named --cy, and so was the cyan design token. Setting --cy: 25% on an element shadowed the colour for that whole subtree, so border: 1px solid var(--cy) became 1px solid 25% — invalid, so the entire declaration was silently dropped. The DOM looked perfect. Name coordinates --hx/--hy.
  • A hotspot sat in empty space. Eyeballed percentages from a downscaled preview. Draw the ellipses onto the actual image with PIL, look at the result, correct, repeat.
  • The HUD panel's stats spilled past its own border. Absolutely-positioned content contributes no height to its parent. Stack the panel states in one CSS grid cell so it sizes to the tallest.
  • The ship loaded below the fold, hiding the entire interaction on arrival. Worth screenshotting before believing the layout.
  • The animation looked broken in every screenshot. Headless Chrome runs only a handful of requestAnimationFrame callbacks, so the torch lerp never ramps. That is the harness, not the code — which is why the prompt asks for a ?scan=x,y param that pins the torch deterministically. Headless also enforces a ~500px minimum viewport, so a 430px window renders at 500 and looks clipped when nothing is wrong.
  • Every image download failed with CERTIFICATE_VERIFY_FAILED. Python had no usable CA bundle. The jobs had all completed server-side, so the fix was to curl them and recover the URLs from higgsfield generate list --json rather than pay to regenerate nine 4K images.

Recap

  • One ship generated twice, with the second pass forbidden from moving it. Not two ships.
  • Check registration with a channel overlay you actually look at. IoU will tell you a perfect pair is broken.
  • One alpha mask from the union of both layers, or the reveal edge shows you where they disagree.
  • Key chroma green yourself. It beats a background-removal model and it is faster.
  • Never shadow a design token with a coordinate variable of the same name.
  • Screenshot it. Layout and visibility bugs do not show up in the DOM.
